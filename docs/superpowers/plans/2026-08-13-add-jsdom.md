# Add jsdom — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Give this repo the ability to test React components and hooks, then use it to close the one gap that motivated it.

**Why now.** Three bugs on this branch lived in untested React effect wiring — a checklist that regressed to zero on success, an unbounded poll, and a stuck read-only gate. Each was caught by review, not tests. Most recently, `useRowSelection`'s retain-visible effect could be no-op'd with all 14 of its tests still passing: the tests exercise the pure reducer, and nothing pins that the hook calls it. That gap is structurally unclosable in a node environment.

**Architecture:** Two Vitest projects rather than one global environment. The existing ~179 files talk to a real Postgres and must stay in `node`; only component and hook tests get `jsdom`.

**Tech Stack:** Vitest 4.1.10, React 19.2.4, jsdom 30, `@testing-library/react` 16.3.2.

## Global Constraints

- **Vitest here is 4.1.10, where `environmentMatchGlobs` was REMOVED** (deprecated in v3). Confirmed absent from the installed type definitions; `test.projects` is the supported API. Do not reach for `environmentMatchGlobs`, and do not trust training-data examples that use it.
- **The node project must keep every existing test in `node`.** These tests hit a real Postgres through `pg`. A DB test silently reassigned to `jsdom` is the main way this change goes wrong, and it may show up as slowness or flakiness rather than a clean failure.
- **`vitest.setup.ts` is load-bearing for the node project** and must keep running there. It pins `TZ=Asia/Jerusalem` (several date tests only prove anything off-UTC) and it hard-fails unless the database name ends in `_test`, which is what stops a test run from mutating dev data. **Do not weaken or bypass that guard**, and do not make the jsdom project inherit a DB requirement it has no use for.
- No test may reach the real Anthropic API.
- Baseline before this change: **179 files / 1475 tests**. Report totals after; a *drop* means a file stopped being collected.
- The suite is flaky against one shared Postgres — re-run a failing file once before believing it.
- `npm run build`, `npx tsc --noEmit` and `npm run lint` must all stay clean.
- **The working tree has pre-existing uncommitted changes that are NOT ours:** `src/app/(dashboard)/board/column.tsx`, `src/app/(dashboard)/layout.tsx`, untracked `src/app/(dashboard)/main-container.tsx`. Never `git add -A`.

### Task 1: The two-project split

**Files:** `package.json`, `vitest.config.ts`, a new jsdom setup file.

- [ ] **Step 1: Install**

`jsdom`, `@testing-library/react`, `@testing-library/dom`, `@testing-library/jest-dom` as devDependencies. `@testing-library/react` 16.3.2 declares React 19 support; `@testing-library/dom` ^10 is its peer and must be explicit.

- [ ] **Step 2: Split `vitest.config.ts` into two projects**

- **node** — every existing test path, `environment: "node"`, `setupFiles: ["./vitest.setup.ts"]`.
- **jsdom** — component and hook tests only, `environment: "jsdom"`, its own setup file.

Choose the jsdom project's include glob deliberately and say why in the report. `tests/components/**` is the obvious seed, but the hook test that motivated this currently lives at `tests/app/row-selection.test.ts`. Either move it or widen the glob — **whichever you choose, the two projects' globs must not overlap.** An overlap means a file runs twice, which inflates the count and hides a miscount.

The shared `resolve.alias` for `@` must apply to both.

- [ ] **Step 3: The jsdom setup file**

Needs `cleanup()` after each test so mounted trees do not leak between tests. It must **not** require `DATABASE_URL`. Keep the `TZ` pin if any date-rendering component test would depend on it.

- [ ] **Step 4: Prove the split is correct**

This is the step that matters:
- Full suite: **179 files / 1475 tests** still, plus nothing lost. Report the totals and the per-project split.
- Confirm a known DB test still runs under `node` — assert on something jsdom-specific being absent, or check the reported project name.
- Confirm a component test runs under `jsdom` — `typeof document !== "undefined"`.
- **Deliberately verify the DB guard still fires** for the node project: point `TEST_DATABASE_URL` at a non-`_test` name and confirm the run hard-fails. Restore afterwards.

- [ ] **Step 5: Commit**

### Task 2: Close the gap that motivated this

**Files:** the `useRowSelection` test.

- [ ] **Step 1: Write a `renderHook` test that pins the wiring**

The requirement, precisely: **a test that fails when the hook stops calling `reconcileSelection`.** Render the hook, select ids, re-render with a narrowed `rows`, assert the stale ids are gone from `selected`.

- [ ] **Step 2: Verify it with the exact mutation that defeated the previous attempt**

In `src/app/(dashboard)/_components/use-row-selection.ts`, replace

```ts
setSelected((prev) => reconcileSelection(prev, rows));
```

with

```ts
setSelected((prev) => prev);
```

and run the test. **It must fail.** Restore and confirm green.

That mutation is the whole point. A previous attempt at this gap verified itself by no-op'ing `reconcileSelection` *itself*, which only proved that the pure-function tests test the pure function — it passed its own drill while leaving the wiring unpinned. Do not repeat that: mutate the **call site**, not the callee.

- [ ] **Step 3: Commit**

## Out of scope

Rewriting the existing pure-function tests in `tests/components/` that were shaped around not having jsdom (`generation-checklist`, `evidence-drawer`). They pass and still have value. Converting them is a separate, larger decision now that the option exists.
